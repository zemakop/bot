# MAX AI Studio — стартовый код коммерческого бота

**Статус: технический прототип, не готов к публичным продажам.**

## Что реализовано
- Тарифы 1 / 3 / 8 часов с предварительными ценами.
- Регистрация по ID пользователя MAX, отдельно для каждого клиента.
- PostgreSQL: пользователи, заказы, оплаченные минуты, активированные сессии, история текста.
- Автоматическая проверка истечения сессии при каждом обращении (без фонового таймера).
- Активация 1/3/8 часов с атомарным списанием оплаченного баланса.
- Ограничение количества текстовых запросов на каждую активацию.
- Интеграция создания платежа ЮKassa с опциональным фискальным чеком и ссылкой.
- Проверка статуса платежа запросом GET в ЮKassa; повторное начисление заблокировано транзакцией.
- Опциональный текстовый ответ GigaChat после подключения коммерческого ключа.
- Команды /start /plans /balance /terms /agree /email /activate /buy.

## Чего в этом архиве пока нет
- Подключённого сервиса генерации/редактирования изображений и видео.
- Загрузки/сохранения файлов из MAX и генерации PDF/DOCX/XLSX/ZIP.
- Админ-панели, очередей задач, хранилища проектов, возвратов и управления подписками.
- Production-подписки MAX на Webhook (сейчас SDK работает в режиме разработки).
- Лимита фактических затрат на токены/медиагенерацию (есть только число текстовых запросов).
- Аудита разрешений на загрузку персональных данных, хранения/удаления файлов, антивируса.
- Полноценного биллинга фискальных чеков с учетом авансов, зачета предоплаты и возвратов.

**Не переключайте ENABLE_PAYMENTS=true, пока бухгалтер/интегратор не подтвердит чеки, НДС и оферту, а тестовый магазин не проверен.**

## Быстрый запуск разработки на Windows
1. Установить Node.js версии 22+ (твой Node 24 подходит) и PostgreSQL.
2. Создать в PostgreSQL пользователя и БД, указать строку подключения в `.env`.
3. Зарегистрировать отдельного бота через подтверждённый профиль ООО на платформе MAX.
4. Скопировать `.env.example` в `.env`; указать `BOT_TOKEN`, `DATABASE_URL`.
5. Оставить `ENABLE_PAYMENTS=false`: на этом этапе деньги не принимаются.
6. В PowerShell в папке проекта выполнить:
   ```powershell
   npm install
   npm test
   npm start
   ```
7. В MAX открыть своего бота, отправить `/start`, проверить `/plans`, `/balance`.
8. Для тестов платёжного webhook потребуется публичный HTTPS-адрес сервера, тестовый магазин ЮKassa и опубликованная оферта.

## Открытие платежей в дальнейшем
- Договор и тестовый магазин ЮKassa на ООО.
- Настройка `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_VAT_CODE`, `SERVICE_URL`.
- ЮKassa -> Интеграция -> HTTP-уведомления -> событие `payment.succeeded`, URL `https://ВАШ-ДОМЕН/yookassa/webhook`.
- Принимать настоящую оплату только после проверки 54-ФЗ и чеков (покупка часов заранее требует особого учёта предоплаты и зачёта).
- Публичный HTTPS, защита вебхуков, rate limiting, мониторинг и бэкапы.
- Приём возвратов, защита от повторного использования устаревших ссылок, юридические документы.

## Бизнес-правила прототипа
- После подтверждённой оплаты минуты добавляются на баланс.
- Кнопка «▶ 3 часа» активирует 180 минут, если баланс достаточен.
- Если есть действующая сессия, активация продлевает её. **Паузы нет.**
- По окончании оплаченного времени новые запросы блокируются.
- Каждый оплаченный час дополнительно даёт 40 текстовых запросов (значение в `.env`).
- Медиаоперации будут оплачиваться отдельными кредитами, а не входить без ограничений в часовую цену.

## Важно перед публичным запуском
- Для российского рынка не опирайтесь на OpenAI API без проверки допустимости обслуживания пользователей в нужных странах. Прототип предлагает GigaChat для текста.
- MAX требует HTTPS Webhook в production.
- У пользователей должна быть действующая оферта, информация об ООО, описание услуги и ограничения доступа.
- Соблюсти 152-ФЗ, хранение персональных данных, политику конфиденциальности и порядок удаления файлов.
- Приём денег ООО: требования 54-ФЗ, чеки/НДС, порядок возврата и зачёта аванса — согласовать с бухгалтером.
- Нагрузочное тестирование до запуска рекламы.

## Технические ограничения данного старта
- Кнопки оплаты возвращают ссылку только при ENABLE_PAYMENTS=true и заполненных реквизитах.
- Ответы текстового ИИ появляются только если настроен GIGACHAT_AUTH_KEY и открыт коммерческий доступ.
- Запуск `npm start` использует long polling MAX, годится для тестов, не для большой аудитории.
- Код прототипа не содержит приватных ключей, паролей или данных компании.

## Работа через Codex

1. Распакуй архив в отдельную папку Windows, например `C:\\Projects\\MAX-AI-Studio`.
2. Открой приложение ChatGPT для Windows и выбери **Codex** в меню слева сверху.
3. Открой локальную папку проекта `C:\\Projects\\MAX-AI-Studio`.
4. Попроси Codex выполнить первое задание из `CODEX_START.md`. Инструкции для агента — в `AGENTS.md`, план развития — в `ROADMAP.md`.
5. Используй `npm install` и `npm test` для первичной проверки. Не указывай настоящие ключи, пока не закончены аудит и подготовка тестовой среды.

Этот архив не находится автоматически в облаке Codex и не загружен на GitHub. Для Codex Cloud потребуется отдельно создать репозиторий, загрузить код, подключить репозиторий и настроить облачную среду.
